# 开销统计

麦麦（MaiBot）插件。查麦麦自己烧了多少 token、花了多少钱、缓存命中率怎么样。

## 功能

| 功能 | 触发方式 |
| --- | --- |
| 查开销 | `/开销 [天数]` 命令，渲染成一张卡片图 |
| LLM 自查 | `check_cost` 工具，用户问「今天花了多少钱」时由模型自己调 |

卡片布局对齐宿主 WebUI 的统计概览页，含五个区块：**统计概览**（花费 / 请求数 / Token / 消息数，各带迷你柱状图和环比）、**Prompt 缓存**（总命中率 + 分模型）、**模型花费分布**、**Token 流向拆解**（缓存命中 / 未命中 / 无缓存信息 / 输出）、**单位成本与效率**（六项指标 + 环比）。

数据来源见下方「关于数据来源：直连宿主数据库」。

## 安装

1. 把仓库内容放进 `MaiBot/plugins/maibot-cost-report/`，目录里必须有 `_manifest.json` 和 `plugin.py`
2. 在 WebUI 插件页启用，或重启麦麦
3. 首次加载会自动生成 `config.toml`

## 要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| MaiBot | 1.3.x / 1.4.x | manifest 里声明的区间是 `1.3.0` ～ `1.4.99` |
| `maibot-plugin-sdk` | 2.4.0 起 | 插件用了 2.4.0 才引入的 `PluginConfigBase`，再低的版本会在 `import` 阶段就失败。2.21.0 已验证 |

SDK 版本超出 manifest 区间时宿主只记 warning、仍会加载，所以下界不要写低——写在 2.0.0 的话，2.0～2.3 的环境里表现是「加载成功然后 ImportError」。

| `report.max_days` | `30` | 允许查询的最大天数，防止 `/开销 9999` 扫表 |

## 关于「最近 24 小时」

宿主的统计窗口按 `now - N 天` 计算，没有自然日边界，所以 `days=1` 得到的是**滚动 24 小时**而不是今天 0 点至今。凌晨查会带上昨天的一部分，白天基本等于今天。

要精确到自然日只能自己扫 `llm_usage` 明细，代价大得多，这里没做。

另外，聚合表按**整点**分桶（`bucket_time >= since` 的第一个桶是 `ceil(since)`），所以缓存命中率那条明细查询也统一从 `ceil(since)` 起算，保证卡片上的「花费」和「缓存命中」是同一个时间窗口。

宿主按**调用次数**降序返回模型，最多 50 个。插件会取满 50 个再按花费排序，尽量避免漏掉「调用少但单价贵」的模型；真的超过 50 个时，卡片页脚会注明「按调用次数取前 50 个模型汇总」。

## 关于数据来源：直连宿主数据库

卡片上那套指标（花费、请求数、Token 流向、缓存命中、回复率、任务失败率、环比）**在宿主的能力体系之外**。

宿主有 7 个 `statistics.local.*` 能力，但都拿不到这张卡片需要的东西：

| 缺什么 | 原因 |
|---|---|
| 输入/输出 Token 拆分 | `token_distribution` 只返回 `total_tokens` |
| 缓存命中 / 未命中 | 聚合表没有缓存字段，只有 `llm_usage` 明细里有 |
| 回复率 | `message_trend` 只按聊天流分组，分不出哪些是机器人自己的发言 |
| 任务失败率、环比 | 没有任何能力暴露 |

所以插件用**只读模式**（`mode=ro`）打开宿主数据库自己查。读的是这几张表：

| 表 | 用途 |
|---|---|
| `statistics_model_hourly` | 模型维度：请求数、输入/输出 Token、花费、按小时序列 |
| `statistics_message_hourly` | 消息总数 |
| `llm_usage` | 缓存命中/未命中明细 |
| `online_time` | 在线时长 |
| `tool_records` | 工具调用成败（算任务失败率） |
| `mai_messages` | 机器人自己的发言数（算回复率），账号从 `bot_platform_accounts` 自动识别 |
| `bot_platform_accounts` | 机器人账号 ID |

**只读、不写入、不改结构**，SQL 全部参数化绑定。

这条路径依赖几个宿主没有承诺过的内部细节：数据库文件名 `MaiBot.db`、它位于「插件数据目录往上两级」、以及上面这几张表的字段名。宿主调整目录布局或表结构时会失效。

**失效时不会静默**：卡片退回简易版（只有花费、Token、模型明细，没有环比和 Token 流向），日志里有一条 `看板数据采集失败，退回简易卡片` 的 warning。路径推算不对时，把 `report.db_path` 填成实际的 `MaiBot.db` 绝对路径即可。

如果完全不想让插件碰数据库，把 `report.show_cache` 关掉——此时只走官方能力，卡片是简易版。

## 关于 magpie 用量（可选）

如果你自己跑了 [magpie](https://github.com/) 这类本地反代网关（把请求转给上游订阅账号），
可以打开 `report.magpie_enabled`，卡片底部会多一个区块：

- 今天用了多少次、多少输入/输出 token、按公开价折算的账面成本
- 上游订阅的配额消耗（7 天窗口 / 5 小时窗口，各一条进度条）
- 与昨天的调用次数对比

**默认关闭**，没装 magpie 的用户完全不受影响——插件不会发任何额外请求，卡片上也不会多区块。

打开后插件会请求 magpie 的两个接口：

| 接口 | 内容 |
|---|---|
| `/v1/magpie/usage` | 30 天汇总 + `series` 按天分桶 |
| `/v1/magpie/quotas` | 订阅配额，Gemini 的 7 天 / 5 小时窗口 |

拉不到数据时这个区块整块消失，不影响卡片其它部分，日志里只有一条 debug。

**成本怎么算的**

magpie 返回的 `cost` 和 `/v1/models` 的定价都是**美元**，而宿主记的其它模型花费是人民币，直接相加会差好几倍。所以插件：

1. 从 magpie 的 `/v1/models` 拿单价（美元 / token）
2. 从宿主 `llm_usage` 拿**完整历史**的 token 量（缓存命中 / 未命中 / 输出分开算）
3. 乘汇率换算成人民币

不用网关的明细成本，是因为 `/v1/magpie/usage/requests` 只返回最近 500 条（约 2.6 天），窗口一长就截断；`llm_usage` 没有这个限制。

**汇率是自动抓的**：每 6 小时从公开汇率源取一次（主备两个源），抓不到才退回 `report.magpie_usd_rate` 的兜底值，并在 10 分钟后重试。不用手动维护。

**要不要计入总花费？**

`report.magpie_count_cost` 控制这个，默认 `true`：

- **开启**：magpie 的账面成本会**按模型**并进「总花费」和「模型花费分布」，看到的是「如果按量付费要花多少」。
  这样模型分布的各项加起来正好等于总花费，不会出现「总额含它、模型却是 0%」的对不上。
- **关闭**：只展示用量和配额，总花费仍按宿主记的 token 计费算。适合上游是包月订阅、
  你只想盯配额消耗、不想让账面价污染统计的情况。

两种模式下区块都会照常显示，只是右上角标注会变成「账面已计入 / 未计入总花费」。

⚠ 注意：magpie 返回的 `cost` 是按公开价折算的**账面值**。如果上游是订阅制（比如 Google AI Pro），
实际不按 token 付费，真正该看的是**配额百分比**。

## 常见问题

**图里的数字和模型配置页对不上？**
卡片上的模型名来自 `statistics_model_hourly.model_name`，就是配置里的模型名（如 `wb-proxy/deepseek-v4.1-flash`），不是 `llm_usage.model_name` 里那个 `model_identifier`（`deepseek-v4.1-flash`）。缓存命中率另外按 `llm_usage.model_assign_name` 分组匹配，两者实测同名；真出现对不上的情况，命中率那一列会显示 `—`，不影响花费和 token。

**缓存命中率显示「—」？**
卡片上会同时提示「读不到 llm_usage，检查数据库路径」。先看日志里那条 `数据库文件不存在` 的 warning，路径不对就把 `report.db_path` 填成 `MaiBot.db` 的绝对路径；路径对但还是「—」，可能是该窗口内没有缓存字段数据，或者数据库被别的进程长时间锁住。

**渲染失败？**
会自动退回纯文本，日志里会有一条「统计图渲染失败」。常见原因是 Playwright 浏览器没装好。

**能查某个具体模型吗？**
目前不支持，只按花费降序列出前 N 个。
